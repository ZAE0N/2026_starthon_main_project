# 서버 실행하기

담당: 전정현. 명세는 `README.md`, 구현 내용은 이 문서입니다.

## 1. 준비

```bash
cd server
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt   # 윈도우
# source .venv/bin/activate && pip install -r requirements.txt  # 리눅스
```

`.env.example` 을 `.env` 로 복사하고 값을 채웁니다. `.env` 는 깃허브에 올라가지 않습니다.

```
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o
APP_TOKEN=
```

**`OPENAI_MODEL` 은 반드시 콘솔에서 확인하고 넣으세요.** 모델 이름은 자주 바뀝니다.
이름이 틀리면 OpenAI 가 404 를 주고, 앱에는 "지금은 분석할 수 없어요" 로만 보입니다.
서버 로그에는 이유가 찍히니 막히면 로그를 먼저 보세요.

## 2. 띄우기

```bash
.venv/Scripts/python.exe -m uvicorn main:app --reload --port 8000
```

기동할 때 `laws.json` 의 8개 항목 순서가 앱과 같은지 확인하고, 다르면 바로 죽습니다.
`laws.json` 을 고쳤으면 서버를 다시 띄워야 반영됩니다.

## 3. 확인

```bash
curl http://127.0.0.1:8000/health
```

계약서 사진으로 전체 흐름을 시험합니다.

```bash
.venv/Scripts/python.exe check.py 계약서.jpg
.venv/Scripts/python.exe check.py 계약서.jpg --token 값   # APP_TOKEN 을 채웠으면
```

`check.py` 는 응답이 앱 계약을 지키는지 항목마다 확인합니다.
앱을 켜서 확인하면 한 번에 1분씩 걸리는 것들입니다.

## 4. 앱에 붙이기

저장소 루트의 `.env` 를 고칩니다.

```
EXPO_PUBLIC_API_URL=http://192.168.0.x:8000    # PC 의 로컬 IP. 끝에 / 금지
EXPO_PUBLIC_API_TOKEN=                          # 서버 APP_TOKEN 과 같은 값
EXPO_PUBLIC_USE_MOCK=false
```

```bash
npx expo start -c
```

**`-c` 를 빼면 안 됩니다.** 캐시 때문에 `.env` 변경이 반영되지 않습니다.

서버는 `--host 0.0.0.0` 으로 띄워야 폰에서 접속됩니다. 폰과 PC 가 같은 와이파이여야 하고,
윈도우 방화벽이 8000 포트를 막고 있으면 허용해야 합니다.

## 상태 코드가 곧 사용자 화면입니다

앱은 상태 코드로 안내 문구를 고릅니다 (`lib/api.ts:164-173`). 마음대로 바꾸면 엉뚱한 화면이 뜹니다.

| 코드 | 서버에서 나는 때 | 앱 화면 |
|---|---|---|
| 200 | 정상 | 결과 화면 |
| 400 | 요청 형식 오류 | 지금은 분석할 수 없어요 |
| 401 | 토큰 불일치 | 지금은 분석할 수 없어요 |
| 413 | 사진이 너무 큼 | 지금은 분석할 수 없어요 |
| **415** | **근로계약서가 아님** | 근로계약서가 아닌 것 같아요 (다시 찍기) |
| **422** | **글자를 못 읽음** | 계약서를 읽지 못했어요 (다시 찍기) |
| 5xx | 서버·OpenAI 오류 | 지금은 분석할 수 없어요 |

**415 는 "계약서가 아님" 판정에만 씁니다.** Content-Type 문제로 415 가 새어 나가면
멀쩡한 계약서를 찍은 사람에게 "근로계약서가 아닌 것 같아요" 가 보입니다.

**FastAPI 의 기본 422 는 400 으로 바꿔 뒀습니다** (`main.py` 의 `_validation_error`).
안 그러면 필드명 오타 같은 개발 실수가 사용자에게 "다시 찍어주세요" 로 보여서
멀쩡한 사진을 계속 다시 찍게 됩니다.

## 앱에 있는 숨은 규칙 하나

`lib/api.ts:191-194` — 8개가 **전부 "확인필요" 이면서 원문 인용이 하나도 없으면**
앱은 200 응답을 버리고 "계약서를 읽지 못했어요" 를 띄웁니다.

그래서 판독에 실패했을 때 "전부 확인필요로 채워서 200" 을 보내면 안 됩니다.
서버가 `inspector.build_result()` 에서 이 경우를 잡아 **422** 로 내보냅니다.

## 토큰

`APP_TOKEN` 이 비어 있으면 서버가 토큰 검사를 건너뜁니다. 로컬 테스트용입니다.

앱은 `EXPO_PUBLIC_API_TOKEN` 이 비어 있으면 `X-App-Token` 헤더를 **아예 보내지 않습니다**.
그래서 **한쪽만 채우면 모든 요청이 401** 이 되고, 앱에는 "지금은 분석할 수 없어요" 로만 보입니다.
둘 다 비우거나 둘 다 같은 값으로 채우세요.

배포할 때는 반드시 채웁니다. 다만 토큰은 앱 번들에 평문으로 들어가서 추출이 가능하므로
(`PROGRESS.md` 의 R7) 크레딧 보호 효과는 제한적입니다. 서버 쪽 rate limit 을 같이 두는 게 맞습니다.
