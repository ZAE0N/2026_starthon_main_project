아르바이트 근로계약서를 사진으로 찍으면 문제가 될 수 있는 조항을 찾아주고, 사장님에게 할 말까지 문장으로 만들어 주는 앱

## 문제 상황 제기

### 부당한 계약 근로의 피해

| 수치 | 출처 |
|---|---|
| 2024년 임금체불액 **2조 448억 원**, 피해 근로자 **28만 3,212명** (사상 최대) | 고용노동부 |
| 최저임금조차 못 받는 근로자 **276만 1천 명 = 전체의 12.5%** (2024) | 최저임금위원회 |
| **숙박·음식점업 최저임금 미만율 33.9%** — 전 업종 1위 | 최저임금위원회 |
| **5인 미만 사업체는 약 10명 중 3명**이 최저임금 미만 | 최저임금위원회 |
| 임금체불의 **67.6%가 30인 미만 사업장** (2026년 1월) | 고용노동부 |

### 계약서를 봐도 확실한 이해가 불가

만 15~18세 알바생 292명 조사 (알바천국, 2026년 5월)

- 근로계약서를 쓰지 않았다 — **19.5%** (만 15세는 26.1%, 학교 밖 청소년은 24.4%)
- 안 쓴 이유 1위 — **"작성해야 하는지 몰라서" 40.4%**
- 계약서를 안 썼을 때 **시정을 요청한 비율 7.0%**

### 인지를 하여도 언급하지 못하는 경우

전남 직업계고 3학년 조사 (전남노동권익센터, 2024)

- 부당한 대우를 겪고도 **"참고 일했다" 61%**
- 계약서를 쓰고 **직접 교부까지 받은 비율 약 39%**

그래서 이 앱은 이러한 점을 해결하기 위한 피드백을 만들어 줍니다.

## 앱의 정체성

```
계약서 촬영 → 조건 2가지 답변 → 판정(6~8초) → 형광펜 그은 계약서 → 결과 → 말할 문장
```

### 가장 중요한 8개 항목 검사

계약 형태 · 시급 · 수습 감액 · 근로시간 · 휴게시간 · 주휴수당 · 위약금 조항 · 명시 항목

판정은 **위법 소지 / 확인 필요 / 문제없음** 세 단계입니다.

### 판정은 AI 가 하지 않습니다.

모델에게 판정을 맡기면 "1년 계약이고 수습이니 9,288원도 괜찮다" 같은 추론을 해서 최저임금 미달이 "문제없음" 으로 나가고, 실험 결과 실제로 그랬습니다.
그래서 **모델은 계약서에서 사실만 읽고, 판정은 코드가 계산합니다.**

| 항목 | 판정 주체 |
|---|---|
| 시급, 수습 감액, 근로시간, 휴게시간, 주휴수당, 명시 항목 | **코드** (`inspector.recompute`, `recompute_time`) |
| 계약 형태, 위약금 조항 | 모델 |

같은 파일을 3번씩 보내 재봤을 때 **임의로 만든 여러 장의 정당하지 않은 계약서와 정당하게 만든 계약서의 판정이 정확하게 분류되었습니다.(32번 확인)**

### 알기 힘든 사실까지 확인

주 60시간·휴게 30분이 적힌 계약서로 실제 측정한 결과

| 답 | 근로시간 | 휴게시간 |
|---|---|---|
| 모름 | 위법 소지 | 위법 소지 |
| 5명 미만 · 성인 | **문제없음** | 위법 소지 |
| 5명 미만 · 만 18세 미만 | **위법 소지** | 위법 소지 |

상시 4명 이하 사업장에는 제50조(주 40시간)가 적용되지 않으므로, 그래서 5명 미만이면 주 60시간을 적어도 그 자체로는 위법이 아닙니다.

반대로 만 18세 미만의 근로시간 한도(제69조)는 별표1 에 들어 있어서 **5명 미만인 곳에서도 그대로 적용됩니다.**

이 기준을 명시할 수 있는 기능을 추가했습니다.ㅁ

### 문제 대목에 표시

판정이 끝나면 방금 찍은 계약서에 문제가 되는 글자 줄 위만 칠해서 보여줍니다.

- 사진의 좌표를 받아 사진에서 **실제 글자 줄을 찾아** 맞춥니다.
   (Otsu 이진화 + 행별 잉크 투영, `server/textlines.py`, 15~25ms)

### 할 말을 문장으로 반환

조항마다 사장님에게 할 말을 두 가지 말투로 만들어줘, 실 사용자들이 말할 수 있게 만듭니다.

## 개발 규칙


1. **화면 하나 = 파일 하나 = 담당자 한 명.**
2. **공통 파일은 총괄 담당자만 고친다** (`types/`, `constants/`, `lib/`, `server/`)
3. **색·글자 크기·여백은 `constants/theme.ts` 에서만 가져온다.** (하드코딩 금지)
4. **Tailwind·CSS·className 을 쓰지 않는다.**
5. **새 패키지는 합의 후 설치.** (설치했으면 PR 설명에 적는다)
6. **PR 은 `develop` 으로.** `main` 과 `develop` 에 직접 push 하지 않는다
7. **중요한 정보(ex: .env 등)는 절대 커밋하지 않는다**
8. **데이터 형식은 `types/` 에 정의.** (임의로 바꾸지 않는다

`package.json` 이 바뀐 PR 을 받으면 **`npm install` 을 다시 돌린다.**

```bash
git pull && npm install && npx expo start -c
```
