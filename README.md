사장님에게 할 말까지 문장으로 만들어 주는 앱이다.

## 어떤 문제를 풀려고 했나

### 피해는 크고, 알바 자리에 몰려 있다

| 수치 | 출처 |
|---|---|
| 2024년 임금체불액 **2조 448억 원**, 피해 근로자 **28만 3,212명** (사상 최대) | 고용노동부 |
| 최저임금조차 못 받는 근로자 **276만 1천 명 = 전체의 12.5%** (2024) | 최저임금위원회 |
| **숙박·음식점업 최저임금 미만율 33.9%** — 전 업종 1위 | 최저임금위원회 |
| **5인 미만 사업체는 약 10명 중 3명**이 최저임금 미만 | 최저임금위원회 |
| 임금체불의 **67.6%가 30인 미만 사업장** (2026년 1월) | 고용노동부 |

숙박·음식점업과 5인 미만 사업장은 아르바이트 자리다.
피해가 가장 작은 사업장에 몰려 있고, 그곳이 바로 법 적용이 달라지는 곳이다.

### 시작점은 계약서인데, 모르고 안 쓴다

만 15~18세 알바생 292명 조사 (알바천국, 2026년 5월)

- 근로계약서를 쓰지 않았다 — **19.5%** (만 15세는 26.1%, 학교 밖 청소년은 24.4%)
- 안 쓴 이유 1위 — **"작성해야 하는지 몰라서" 40.4%**
- 계약서를 안 썼을 때 **시정을 요청한 비율 7.0%**

### 알아도 말을 못 꺼낸다

전남 직업계고 3학년 조사 (전남노동권익센터, 2024)

- 부당한 대우를 겪고도 **"참고 일했다" 61%**
- 계약서를 쓰고 **직접 교부까지 받은 비율 약 39%**

**정리하면 두 가지다.** 계약서에 무엇이 문제인지 모르고, 알아도 말을 못 꺼낸다.
그래서 이 앱은 판정만 주지 않고 **할 말을 문장으로** 만들어 준다.

## 무엇을 하는 앱인가

```
계약서 촬영 → 조건 2가지 답변 → 판정(6~8초) → 형광펜 그은 계약서 → 결과 → 말할 문장
```

### 8개 항목을 본다

계약 형태 · 시급 · 수습 감액 · 근로시간 · 휴게시간 · 주휴수당 · 위약금 조항 · 명시 항목

판정은 **위법 소지 / 확인 필요 / 문제없음** 세 단계다.
애매하면 "확인 필요" 로 둔다. 틀릴 거면 안전한 쪽으로 틀리는 편이 낫다.

### 판정은 AI 가 하지 않는다

이 프로젝트에서 제일 신경 쓴 부분이다.

모델에게 판정을 맡기면 "1년 계약이고 수습이니 9,288원도 괜찮다" 같은 추론을 해서
최저임금 미달이 "문제없음" 으로 나간다. 실제로 그랬다.
그래서 **모델은 계약서에서 사실만 읽고, 판정은 코드가 계산한다.**

| 항목 | 누가 판정하나 |
|---|---|
| 시급, 수습 감액, 근로시간, 휴게시간, 주휴수당, 명시 항목 | **코드** (`inspector.recompute`, `recompute_time`) |
| 계약 형태, 위약금 조항 | 모델 |

조문 번호와 전문도 모델이 만들지 않는다. `server/laws.json` 에 적어두고 서버가 채운다.
모델이 법을 지어내면 그럴듯하게 틀린 문장이 나오고, 사용자는 그걸 법이라고 믿는다.

같은 파일을 3번씩 보내 재봤을 때 **4장 32개 판정이 전부 같았다.**

### 사업장 규모와 나이를 묻는다

촬영 전에 두 가지를 묻는다. 같은 계약서라도 답에 따라 판정이 달라진다.

주 60시간·휴게 30분이 적힌 계약서로 실제 측정한 결과다.

| 답 | 근로시간 | 휴게시간 |
|---|---|---|
| 모름 | 위법 소지 | 위법 소지 |
| 5명 미만 · 성인 | **문제없음** | 위법 소지 |
| 5명 미만 · 만 18세 미만 | **위법 소지** | 위법 소지 |

근로기준법 시행령 별표1 을 코드로 옮긴 결과다.
상시 4명 이하 사업장에는 제50조(주 40시간)가 적용되지 않는다. 그래서 5명 미만이면
주 60시간을 적어도 그 자체로는 위법이 아니다. 이걸 모르고 판정하면 **없는 위법을
알려주게 된다.**

반대로 만 18세 미만의 근로시간 한도(제69조)는 별표1 에 들어 있어서
**5명 미만인 곳에서도 그대로 적용된다.** 성인 기준으로 보면 위반을 놓친다.

별표1 원문은 대조해서 확인했다. 우리 8개 항목 중 5인 미만에서 빠지는 것은
`hours`(제50조) 하나뿐이다. 근거는 `PROGRESS.md` 의 "법령 검증" 절에 있다.

안 고르면 5인 이상·만 18세 이상 기준으로 본다. 미성년 기준이 더 엄격해서,
성인인데 그 기준으로 보면 없는 위법을 만들어낸다.
어느 기준으로 봤는지는 결과 화면에 항상 적힌다.

### 문제 대목에 형광펜을 긋는다

판정이 끝나면 방금 찍은 계약서에 문제가 되는 **글자 줄 위만** 칠해서 보여준다.

위치는 모델에게 물어서 받지만, 그냥 물으면 표에서 한 칸씩 밀린다.
모델이 좌표를 재지 않고 짐작하기 때문이다.

1. 사진 위쪽과 왼쪽에 **눈금자를 그려서** 보낸다 → 짐작 대신 눈금을 읽는다
2. 받은 좌표를 힌트로만 쓰고, 사진에서 **실제 글자 줄을 찾아** 맞춘다
   (Otsu 이진화 + 행별 잉크 투영, `server/textlines.py`, 15~25ms)

시나리오1 임금 줄 기준 오차가 0.08 에서 **0.004** 로 줄었다.

### 못 쓸 사진은 판정 전에 돌려보낸다

흐리거나 잘린 사진을 모델에 보내면 "못 읽었다" 고 하지 않고 보이는 일부로
판정을 만들어 버린다. 사용자는 그게 틀린 줄 모른다.

그래서 판정을 시작하기 전에 서버가 글자 줄을 찾아보고, 잘렸거나 너무 작거나
글자가 거의 없으면 이유를 붙여 돌려보낸다. 27~58ms 에 끝나고 **OpenAI 호출을
하지 않는다.**

### 할 말을 문장으로 준다

조항마다 사장님에게 할 말을 두 가지 말투로 만들어 준다.
"참고 일했다 61%" 를 겨냥한 기능이다.

## ChatGPT 에 사진 올리면 안 되나

받을 만한 질문이라 따로 적는다. 세 가지가 다르다.

**1. 판정을 코드가 한다.** ChatGPT 는 모델이 법을 기억해서 판정한다. 그래서
"1년 계약이고 수습이니 9,288원도 괜찮다" 같은 추론이 나온다. 우리는 모델에게
숫자만 읽게 하고 최저임금·근로시간·휴게시간·주휴수당·명시항목을 코드로
계산한다. 조문도 `laws.json` 에서 가져온다. 같은 사진에 같은 답이 나온다.

**2. 사업장 규모와 나이를 반영한다.** 근로기준법 시행령 별표1 을 코드로 옮겨서,
5인 미만이면 주 40시간 한도를 적용하지 않고 만 18세 미만이면 주 35시간으로 본다.
사진만 올려서는 이 조건을 알 수 없다.

**3. 판정에서 끝내지 않는다.** 문제가 어디에 적혀 있는지 계약서에 표시해 주고,
사장님에게 할 말을 문장으로 준다. 조사에서 부당한 대우를 겪고도 61%가 참고
일했다. 몰라서가 아니라 말을 못 꺼내서다.

## 개발 규칙

전문은 [`DEV_RULES.md`](DEV_RULES.md), AI 에게 붙여넣을 규칙은
[`AGENTS.md`](AGENTS.md) 에 있다. 핵심만 적는다.

1. **화면 하나 = 파일 하나 = 담당자 한 명.** 남의 파일은 안 고친다
2. **공통 파일은 전정현만 고친다** (`types/`, `constants/`, `lib/`, `server/`)
3. **색·글자 크기·여백은 `constants/theme.ts` 에서만 가져온다.** 하드코딩 금지
4. **Tailwind·CSS·className 을 쓰지 않는다.** React Native 라서 동작하지 않는다
5. **새 패키지는 합의 후 설치.** 설치했으면 PR 설명에 적는다
6. **PR 은 `develop` 으로.** `main` 과 `develop` 에 직접 push 하지 않는다
7. **`.env`, 실제 계약서 사진, `node_modules` 는 커밋하지 않는다**
8. **데이터 형식은 `types/` 에 정의.** 임의로 바꾸지 않는다

`package.json` 이 바뀐 PR 을 받으면 **`npm install` 을 반드시 다시 돌린다.**
안 하면 Metro 가 기동할 때 죽는다. 두 번 겪었다.

```bash
git pull && npm install && npx expo start -c
```

## 개인정보

- 판정을 위해 사진이 분석 서버를 거쳐 외부 AI 서비스로 간다
- **우리 서버는 사진을 저장하지 않는다.** 다시 인코딩하면서 EXIF(촬영 위치 포함)도 지운다
- 판정 결과와 사진은 폰 안에만 저장된다. 앱을 지우면 함께 지워진다
- AI 서비스 제공자의 보관 정책까지는 우리가 정하지 못한다

메인 화면 아래에 이 내용을 한 줄로 항상 띄운다 (`copy.privacyShort`).
긴 안내문(`copy.privacyLong`)은 써 두었지만 아직 화면에 붙이지 않았다.

## 아직 못 한 것

솔직하게 적는다. 제출 시점 기준이다.

- **실제 종이 계약서를 폰으로 찍어서 검증하지 못했다.** 지금까지의 판정·형광펜
  정확도는 전부 화면에서 렌더한 계약서 이미지로 재 본 값이다. 종이를 찍으면
  기울고 그림자가 져서 더 나빠질 수 있다
- **폰에서 실시간 문서 인식이 안 된다.** Expo Go 에서 카메라 미리보기 프레임을
  받아올 방법이 없다. 그래서 폰은 기울기(가속도 센서)로, 웹은 실제 문서 테두리로
  가이드 색을 바꾼다. 같은 색에 기준이 다르므로 문구도 다르게 썼다
- **OCR 을 붙이지 않았다.** 지금은 모델이 인용한 문장(`original`)이 계약서에 정말
  있는지 확인할 수단이 없다. OCR 로 인용과 숫자를 교차 검증하는 것이 다음 순서다
- **첫 실행 개인정보 안내를 붙이지 않았다.** 긴 안내문(`copy.privacyLong`)은
  작성돼 있는데 화면에 연결하지 않았다. 지금은 메인 화면의 한 줄 요약만 있다
- `server/laws.json` 의 최저임금·조문은 2026-09-11 기준이다. 해가 바뀌면 고쳐야 한다
- `main` 브랜치가 `develop` 보다 뒤처져 있다. 제출 전에 머지해야 한다
